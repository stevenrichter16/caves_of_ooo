# Farra and Edden: source-derived native poses

Farra Sprig uses the extracted `western-shopkeeper-sprite` body; Edden Brack uses `east-robed-resident-sprite`. These are new native actor views for the two additional residents. The original 71 scene owners and their source sprites remain unchanged.

`ArtTools/morrowfast_actor_sheets.py` preserves body alpha exactly and changes only selected cap pixels in the upper 14 source rows. It keeps their original brightness while shifting Farra's cap toward weathered olive and Edden's toward muted blue-grey. The faces, hands and lower garments preserve source pixels. No ground/contact PNG is used. `provenance.json` records source and output hashes, pixel offsets, pivots, palette rule and the repeated-pose limitation.

Each 192×1024 sheet contains sixteen 48×64 rows, with only the first of four columns populated. Every row repeats the same body pose. Each native state and facing uses one frame; casting uses the existing static Attack fallback. Movement interpolation and native action gestures continue to work, but these sheets do not claim to contain newly drawn directional, walking, fighting or casting animation.

The runtime catalog mappings are `MorrowfastFarra` → `actor.morrowfast_farra` and `MorrowfastEdden` → `actor.morrowfast_edden`. Their sheets live under `SceneArt/Morrowfast/Art/actors/`, imported through the existing scoped readable Morrowfast texture importer. Native catalog slicing uses 41 PPU. Pivots preserve the original body's authored foot point inside its transparent frame.

`comparison.png` was visually inspected at integer enlargement: both silhouettes remain intact, cap palette differences are restrained, and neither actor carries a rectangle of paving. Script tests passed 2/2 after the missing exporter module was first observed RED. Native resource/alpha/state-count tests and the renderer eligibility-order countercheck await the Unity RED→GREEN cycle owned by the root integration.

Native RED was captured in `Docs/Verification/Morrowfast/native-habitat-input-art-red.xml`: both new actor catalog lookups returned false before the entries and resources were installed; the unrelated terrain predicate counter also failed before reordering. The production entries and PNGs are now exported, and the next native run checks actual imported alpha and the full runtime catalog's state/facing slices. The root integration has updated the extra residents' explicit VisualID values to these unique entries.

The two initial new-asset failures therefore were not clean evidence of a missing resource; the Python exporter's missing-module RED remains the causal asset-generation prerequisite.
