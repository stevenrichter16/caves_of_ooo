# Morrowfast native art contract

The Unity art exporter is `ArtTools/morrowfast_unity_export.py`; run it from the repository with `python3 ArtTools/morrowfast_unity_export.py`. Its tests are `python3 -m unittest ArtTools.test_morrowfast_unity_export`.

It reads the final browser source manifest, validates owner/layer relationships and image dimensions, independently composites the default scene against reference.png, and copies every PNG byte-for-byte into `Assets/Resources/SceneArt/Morrowfast/Art`. The resulting `art-definition.json` is separate from the native gameplay `definition.json`. Source-derived content remains distinguishable from Imagegen-inferred interiors and concealed surfaces in source provenance.

All source pixels remain at one uniform 40.96 pixels per world unit, mapping the complete 1536×1024 canvas to x21.25..58.75, y0..25. The browser's 8px navigation grid is only an extraction review tool. Native 80×25 geometry and interaction anchors come from the gameplay runtime. Its `GetAuthoredAnchor(id)` supplies the reference cell for view translation; correcting an authored native anchor must not shift an intact source component in the image.

The presenter owns sprites, source alpha picking, per-cell fog, roof cutaways and object visibility. Gameplay owns real entity identity, collision, doors, removal, inventory, AI, services and persistence. A moved owner translates its actual source sprite by the change in its native cell; source ground/contact collars are hidden while displaced. Missing/dead/inventory-owned entities cannot leave a duplicate figure in the original source position. Roof cutaway exposes separately generated rooms; it does not remove walls or their collision.

The root integration owns shared ZoneRenderer, CameraFollow, EnvironmentSpriteRenderer and AnimatedEntityRenderer hooks. The native presenter must release its claims when disabled, unloaded or unable to import a source asset. Visual fallback remains playable.

## Native presentation implementation and verification

The native adapter now lives in `Assets/Scripts/Presentation/Rendering/MorrowfastScenePresenter.cs`, with independently validated `MorrowfastArtDefinition` metadata, a narrowly scoped `MorrowfastSceneArtImporter`, and an unlit source-color shader modulated by native fog. This is CoO-original presentation work; it makes no claim of a Qud art pipeline port.

The runtime contract is `CavesOfOoo.Core.MorrowfastSceneRuntime`: `IsActive(zone)`, `FindOwner(zone,id)`, `IsPresent(zone,id)`, `IsDoorOpen(zone,id)`, `IsRoofLifted(zone,id)`, `GetAuthoredAnchor(id)`, and `GetRoomAt(zone,x,y)`. Native room membership is authoritative for automatic cutaways. The source polygons remain useful for extraction metadata and review, but must not override a corrected native door/interior cell.

The shared renderers must query `IsRenderedEntity` before drawing an authored NPC or creature through their normal actor visual catalog. Source views release that claim when outside the art or absent. Fixed authored terrain uses the `MorrowfastAuthoredTerrain` tag (or `morrowfast-terrain:` ID prefix) and is suppressed only while this presenter successfully owns the scene. A moved actor uses its existing source pose translated to its real cell; there are no invented directional animation frames in this export.

Performance: assets, source alpha, material and overlap precedence load once per binding. Per-render invalidation reuses its owner maps, room maps, fog array and material property block; there is no separate Update or LateUpdate polling loop. The adapter mutates only its owned renderer objects and textures. Gameplay owns dirty-cell notifications. `IsRenderedEntity` scans the 145 cached layers; it never parses metadata or loads a resource on a miss. Native PlayMode profiling remains a root integration gate.

Verification status for this work slice: Python exporter tests passed 5/5, copying 147 assets and independently recomposing an intact 0-pixel-difference result. A float32 emulation of the native configured source-depth ordering also preserved 0 differences. Unity compile RED was observed before production classes were written; Unity GREEN and GPU screenshots are pending the shared native runtime integration. The added EditMode suites cover the actual imported resources, configured enabled-renderer composite, native owner movement/removal, automatic interior membership, real doors, fog and release, plus 30 malformed-metadata counterchecks. Pixel reconstruction checks imported pixels and renderer ordering, and does not substitute for inspecting actual GPU color, camera framing, motion and player readability.

Self-review: corrected the assumption that a source NPC can be suppressed solely through EnvironmentSpriteRenderer; AnimatedEntityRenderer independently traverses the actor catalog, so the integration needs both hooks. Corrected the assumption that native interior membership always matches a fine-grid source polygon. A ground-plane bridge sorting case was added as an intended failing test before changing bridge presentation. Remaining visual limitations are the source pose per actor and deliberately inferred concealed interiors; neither is described as an extracted unseen original surface.

## Shared presentation hooks

The native shared integration now also updates `ZoneRenderer`, `CameraFollow`, and `AnimatedEntityRenderer`. The pre-implementation Unity console run captured two precise missing-API RED errors in `MorrowfastSharedPresentationTests.cs`: `AnimatedEntityRenderer.SetSourceEntityPredicate` (line 39 at that revision) and `ZoneRenderer.MorrowfastPresenter` (line 51). Root confirmed the gameplay runtime compiled successfully before these shared production edits. This is a compile-prerequisite RED, not an assertion that the new camera and actor behavior had already executed.

ZoneRenderer now includes Morrowfast in successful art ownership, alpha-based scene picking, dirty/full refresh, pause/toggle visibility, binding and cleanup. Fresh or mixed water coatings retain native gameplay marks; only the authored terrain's permanent plain-water projection is omitted. Visible actors within either source scene retain the existing white CPU tint policy. The animated actor catalog excludes bodies currently drawn by a source presenter and releases already acquired duplicates at sync; when source ownership ends, normal views may resume. This predicate is also applied to the existing Felling dressing presenter rather than suppressing any unrelated blueprint globally.

CameraFollow reuses the existing 3:2 letterbox/clear-camera behavior. Morrowfast fits the complete image at center (40,12.5), half-height 12.5 when inside the artwork. Player and Look tracking on horizontal approach routes continue to pan into view. Disabling source art, leaving the zone or opening fullscreen UI releases its framing. Existing Felling's center (40,16) and 32-row upper projection remain unchanged. Native top-edge player sprite clipping remains a live screenshot check, because the frame fits y0..25 exactly while the ordinary player sprite extends above its row-0 feet.

The first native Morrowfast EditMode run completed 138 cases and captured the intended bridge assertion RED: `WalkingAcrossTheBridgeCannotPutTheBridgeSurfaceOverTheActor` expected sorting order less than 6, actual 6. The bridge's source sprite/contact contributions are now ground-layer views, so native actors remain above the walking surface when crossing in either direction. Root is rerunning the actual imported composite and shared-hook suites after this fix; the prior run's other two failures belonged to gameplay/roof fixtures handled separately.
