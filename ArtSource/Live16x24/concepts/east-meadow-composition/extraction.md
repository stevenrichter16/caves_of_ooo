# East meadow composition extraction

Source: actual `Docs/Verification/Live16x24/east-meadow-before64-approach.png`,
1280×800 Unity Game capture. Ordinary Continue from an earned pre-East seed64
fixture, border entry and movement to7,18. All entities and visibility are real.

`concept.png` is an imagegen reinterpretation, not gameplay evidence. The generated
image alters resolution, invents gradients, smooths sprite details and moves some
visibility boundaries; reject all those changes. Its useful suggestion is to
break the regular flower rows into unequal groups with connected open interiors.
It over-thins the meadow; retain substantially more flowers in production.

Parts and owners:

- Retained pink flowers: existing persistent `CharmFlowers` terrain owners and
  approved native frame. No replacement art, animation, pickup or yield invented.
- Openings and uneven fringe: remove only a subset of original cold-generated
  flower placements. Use existing Grass owners below them; no new overlay.
- Trees, bushes, routes, visibility, court, crops and forge: unchanged owners and
  existing sprites. Maintain exact optional workpad admission at old flower cells.
- Existing saves and previously visited zones: authoritative saved owners;
  no migration, live thinning or renderer hiding.

Native production is the editable deterministic placement source, not a scaled
copy of imagegen pixels. Reuse native16×24 sprites at their existing positions.
Target clear groups, visible meadow identity and quiet margins; verify output
against actual before/after game captures. No new shared atlas or per-frame work.

Reference context: the existing project reference library's low-density readable
roguelike composition and readable silhouettes; no reference pixels are imported.
This is original CoO composition, not a Qud asset or mechanics parity claim.
