# Overwrit environment — restrained scraped-ground revision

Source-only first candidate for the current gray-graded rim and blank formations. This128×24 atlas preserves the existing eight-frame contract. Only the ground0–3 family is eligible for revision; dominant quiet0 remains exact, and the actual pixel changes occur in variants1–3. Clipped growth4/5, bench6 and waymarker7 retain their source cells, state metadata, original palette values and all1,536 RGBA pixels. The original overwrit-materials source PNG, cells, manifest, editable blend and builder are preserved in place.

## Material interpretation

The author read CLAUDE.md and the phase plan and viewed both current actual before images, the generated two-view reference and critique. Adopted: flat scraped abrasion and rubbed/erased traces in a mostly empty gray field. Rejected: the concept's changed camera/HUD, broad multi-cell marks presented as if four native cells could reproduce them, and any invented road, paving, pit, raised chip, vegetation or landmark. No generated pixels are traced, sampled or rescaled.

The exact base stays A7A292 and quiet0 contains no motif. Existing grading and75% quiet coordinate selection are unchanged. Variants1–3 place irregular shallow broken wear toward different portions of the cell, with subdued erased traces rather than central outlined islands. All tile boundaries remain the common base. Each ground frame retains at least320 of384 base pixels. The strongest ground difference from base remains nine RGB levels; no bright object chip or dark pit is introduced.

The joined study uses the existing selector and shows source material only. It cannot reproduce actual visibility, tone mapping or map context. Author self-review watch: short abrasion fragments may still repeat or become too faint under the regional grade. Actual matched rim/blank comparison governs acceptance. Intentional emptiness is preserved; this is not the separately planned chunk-population work or a whole-area polish claim.

## Editable source and bounded checks

Tools/Live16x24/build_overwrit_environment.py narrowly adapts the established native Beating source workflow. It reads the approved cells, authors original named unit-quads for the revised ground and exports through existing Blender model/camera/instance helpers. Pillow only reads export pixels for verification. No raster image editing is used.

source-red.json retains the genuine missing-source verification failure before the first build; it is not a Unity/native-test claim. It rejects deliberate changes to the preserved bench, ground opacity, quiet0 and tile edge. Sixteen relevant original source/helper/runtime-contract/reference/before pins remain exact; no foreign metadata is guarded. The runtime PNG hash is recorded as initial provenance rather than held as an active guard, because root owns its authorized import.

Two fresh exports match in native atlas, source cells, palette, contact and joined-study bytes. Both saved blends reopen to1,782 exact unit-quads in38 named mesh groups with correct palette/materials, coordinates and no animation. Binary blend identity is not claimed. One first-build packet is retained under verification/rebuild-first, with final identity and frozen-handoff receipts. No duplicate original approved atlas packet is created.

## Reproduce

Run from repository root:

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --threads 4 --python Tools/Live16x24/build_overwrit_environment.py -- --build
python3 Tools/Live16x24/build_overwrit_environment.py --verify
/Applications/Blender.app/Contents/MacOS/Blender --background ArtSource/Live16x24/overwrit-environment/editable.blend --threads 4 --python Tools/Live16x24/build_overwrit_environment.py -- --inspect-blend
```
