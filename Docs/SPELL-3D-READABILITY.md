## Validation and honesty bounds

Automated checks can verify sample finiteness, imported geometry/alpha/emission, bounded view allocation, prioritization, copied contacts, fog clipping, unchanged camera data, cancellation/modes, real command outcomes and original file preservation. Native GPU captures and paced playback assess apparent brightness, connected density, character readability and motion. A finite capture cannot prove long-session comfort or shipped-build performance. Previously observed Editor stalls remain recorded and must not be hidden by clock caps, changed pass criteria, or discarded failing runs.

## Implementation and ownership

The runtime selects an owned material from each validated piece's metadata (`Glow` → soft glow, otherwise `Emission > 0` → luminous, otherwise the original Palette material). Per-piece property blocks carry the already-linear color and bounded emission. Soft glow uses exported static vertex-alpha gradients with depth testing and the shared physical-cell fog function; it adds no post-processing, light sources or camera settings. Essential geometry is scheduled and drawn before optional particles. Target-bound impacts wait for the copied contact time, and existing conditions still decide frozen/pacified/utility accents.

## Follow-up: preserve an unseen contact across a long frame

The two failed native runs expose a real presentation policy gap. A long frame can advance an active cast from anticipation directly beyond clear, removing it before any contact geometry is sampled. The user requested conspicuous, comfortable animations; fixing this observed skip is within that scope. This is an explicit change from the earlier plan to preserve every native playback delta. It is **not** a reinterpretation of the two failed runs as passes, a weakened audit gate, a shader/art change, or a fix for the underlying Editor stall.

Pre-implementation sweep:

| Source / premise | Verified correction and implementation boundary |
| --- | --- |
| Native scenario `CommandCase`, `ZoneRenderer` update branches | No doubled clock: the scenario resolves commands and observes; the normal renderer/coordinator advances existing casts once, plus a zero-delta render after queue acceptance. |
| `NativeSpellFxRenderer.Update` | It adds the requested delta and removes `Age >= Duration` before sampling. A .56-second advance from .10 can skip an entire contact-to-clear interval. |
| `WorldFxCoordinator.Update`, `WorldFxPlayback.Tick` | Native handles must use the same recovered presentation delta as their meshes. Their raw wall elapsed time and five-second hard timeout must remain authoritative. ASCII/sprite clocks remain unchanged. |
| Existing native speed tests | A .313-second wall update at 2× intentionally completes a .625-second effect. Preserve that behavior. Recovery is limited to unusually long **wall** frames (at least .4 seconds) that would wholly cross a still-unseen native contact-to-clear interval. It is not a blanket delta cap. |
| Scheduled native content and contact sampling | Empty/gesture-only native entries get no invented checkpoint. Only actually scheduled non-gather geometry with a positive contact pose can qualify. A cast already at/past contact never replays its impact. |
| Imported caster gestures | Keep their existing independent lifetime and controller restoration; do not rewind a completed gesture. The earlier-LateUpdate stale-delta concern is a separate unconfirmed hypothesis, not an established cause or a fix claimed here. |

Planned bounded implementation: select a recovered native step before ticking handles, stopping at the earliest eligible still-unseen contact when a long frame would otherwise cross its entire remaining visible interval. Advance all native handles and meshes by that same step. Continue to account for full raw wall time, preserve all cancellation paths, and record the raw/requested/applied presentation deltas in a diagnostic when recovery is applied. Ordinary frames and casts that have already reached contact retain their original timing. The guarantee is narrowly preventing one wholly skipped contact interval; repeated long frames, invisible/occluded art, and the underlying Editor hitch are not solved by this policy. Assertion RED tests and unchanged pre-existing tests precede the production edit.
