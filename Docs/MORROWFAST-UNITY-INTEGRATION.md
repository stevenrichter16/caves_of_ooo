# Morrowfast native Unity integration

Status: **implementation and automated verification in progress; native acceptance pending**. The user has authorized integrating the complete Morrowfast settlement into Unity. This is a local Caves of Ooo feature using the existing native systems, not a claim of newly ported Qud parity. The approved source and completed art workbench remain preserved in `ArtSource/Morrowfast/`.

## Intended playable result

The player can walk south from the Felling at `Overworld.3.5.0` into Morrowfast at `Overworld.3.6.0`, return north, and enter the settlement through ordinary world-map descent. The five existing house doors have real open/closed collision and lead to furnished interiors with matching roof cutaway. The 71 source owners retain independent identities, while local residents, fauna, containers, pantry goods, water, trade and authored quest/service outcomes use actual native state. Returning or loading a save must not reset doors, looted goods, inventories, residents or consent choices.

Detailed setting, names and proposal history are in [the settlement design](FELLING-SOUTH-SETTLEMENT-DESIGN.md). The [earlier Unity handoff](FELLING-SOUTH-UNITY-HANDOFF.md) is an architectural reference; corrections below supersede outdated assumptions in that handoff. The art package's successful raster/browser checks do not establish native implementation.

## Agreed runtime contract

Namespace `CavesOfOoo.Core`:

- `MorrowfastSceneDefinition.Load()`, `Parse(string)`, `Validate()`. Owner data: `id`, `name`, `kind`, `description`, `roomId`, `anchorX/Y`, `mutable`, `blocksMovement`, `footprint` and traversable `bridgeSupport`. Cells declare `x/y/solid/opaque/water/interior`. Buildings declare `id/roofId/doorId/entryX/entryY/interior`.
- `MorrowfastSceneRuntime.ZoneID = "Overworld.3.6.0"`; `IsActive`, `Install(zone,factory,preserveExisting=false)`, `UpgradeCachedZone`, `FindOwner`, `GetState`, `IsPresent`, `IsDoorOpen`, `IsRoofLifted`, `GetAuthoredAnchor`. Installation stages required data and entities before mutating a zone.
- `MorrowfastDoorPart.ComponentId`, `TrySetOpen(actor,zone,bool)`, `IsOpen`, `OpenMorrowfastDoor` and `CloseMorrowfastDoor`.
- `MorrowfastPropPart.ComponentId`, `TryRemove(actor,zone)`, `TrySetRoofLifted(actor,zone,bool)`, `ClearCommand = "ClearMorrowfastProp"`, `RoofCommand = "ToggleMorrowfastRoof"`.
- Scene state persists `Revision`, `RemovedIds`, `OpenDoorIds`, and `LiftedRoofIds`; additional content state follows the owning native system. This list is a test contract, not permission to duplicate quest or merchant inventories into scene state strings.

`WithinOwnerReach` and `BlockingOwner` connect large source footprints to real native interaction and collision. The native C+direction chooser resolves a footprint cell to its actual owner; the audit verifies that exact selected entity. `MorrowfastScenePresenter` exposes `IsReady/CurrentZone/Failure/ComponentCount/IsRoomRevealed/IsRenderedEntity`. Tests assert player-observable invariants from the exported native layout rather than pinning accidental furniture coordinates or assuming every source object's entire image rectangle blocks movement.

Native residents use `MorrowfastContent.ResidentIds`: Nemm, Hesta, Vennit, Pell, Orrit, Sella, Farra and Edden. Three optional quests are `MorrowfastReturnNotch`, `MorrowfastBell` and `MorrowfastSupper`. The native audit follows actual dialogue topics and the `MorrowfastAction` choices; world work uses `MorrowfastInspectCord`, `MorrowfastLoudBell`, `MorrowfastRingBell` and `MorrowfastMoveSupperStool`. Guest beds use `MorrowfastRestGuestBed`. Quest completion is read from `StoryletPart.Current` on the world entity, not an assumed player part.

## Implementation and verification slices

1. **Definition and world access:** validate the complete source-owner graph and 2000-cell native geometry; load the canonical zone through ordinary world generation; maintain all cardinal exits and correct Felling adjacency. Tests precede runtime implementation, with raw RED evidence saved by the coordinating Unity operator.
2. **Owner state, doors and interiors:** install one durable source owner per manifest owner; expose appropriate menus; enter all five buildings; open, close and refuse occupied closure; preserve fixed structure and actor collision when a roof changes. Add wrong-zone, forged-owner, repeated-action and dead/detached actor counterchecks.
3. **Native content:** wire the named residents, independent native fauna, containers, pantry loot/pickup/drop, water, existing trade and rest, plus the agreed local quest outcomes. Test actual item and currency deltas, exact receiver identity, repeated-action refusal and consent paths. Art displays cannot create duplicate merchant stock.
4. **Persistence and migration:** round-trip active and cached Morrowfast through the production session serializer; keep unknown saved occupants, moved objects, deaths, consumption, door state, merchant depletion and quest decisions. Reentry is not a respawn operation. Old maps receive only the intended authored addition.
5. **Native presentation and Play audit:** start an ordinary isolated new game, navigate to Felling, walk south into Morrowfast, exercise the interactions with actual keys, F5/F6, leave/reenter and return north. Capture rendered intact, interior, door, removed-object backing and loaded-state views; report actual profiler markers with observation overhead identified.

## Dedicated adversarial acceptance

The bounded suite targets state atomicity, parser boundaries, ownership identity, multi-instance isolation, repeated calls, save reflection and cross-system travel. A passing case is paired with a meaningful refusal/control where the invariant has two branches.

- Empty/malformed definitions, duplicate IDs/cells, out-of-bounds/nonfinite data, missing building references and unsafe resource paths are rejected before a partial scene can be installed.
- Fresh canonical generation activates Morrowfast; an unrelated zone stays unchanged. All source IDs resolve exactly once. The state carrier is ordinary ground, not a visible implementation object.
- The ordinary Felling south-edge transition enters Morrowfast at its north side and reverses correctly. Opening the five real doors makes every room and every intended owner approach reachable while accounting for living blockers; closed doors exclude their interiors.
- Valid clear/door/roof actions change only their owner/state. Null, remote, dead, detached, wrong-zone, forged, displaced or already-consumed owners do not. Inherited mutable flags cannot turn walls or creatures into generic disposable art.
- Opening and closing a door changes its actual footprint collision; roof visibility alone does not. Closing on the player or another solid actor fails without consuming energy or dirtying unrelated state.
- Real session save/load preserves altered doors, a roof state, moved furniture, looted pantry goods and a foreign marked item. Cache upgrade is idempotent; missing required blueprints cannot erase the original zone.
- Native trade and quest tests assert concrete owned inventories, purse/reward changes and repeated/refused action controls once the final content contracts are available. No test reports a dialogue card as a completed transaction.

## Native audit controls and evidence

The new audit and intact-preview menus mirror Felling's ordinary bootstrap and `NativeSaveIsolation`. The audit queues keyboard press and release edges for full Input System frames, observes the production scaled-time repeat gate and records exact failure context instead of retrying a rejected key until it appears to work. Native pathfinding observes actual `BlocksMovement`; only temporary mobile occupancy permits bounded rerouting/waiting.

Implemented audit sequence: new game → `<` world map → Felling `(3,5)` → walk to its south edge → Morrowfast north arrival → all five house doors/interiors and manual roofs → all 71 source owners examined through their exact native menus → eight residents and two living creatures → public water, crate and pantry loot → inventory drop/pickup → both merchants' actual purchase and sale → all three local quests and guest rest → clear a multi-cell stall → F5/F6 → walk north into Felling and back → verify persistent scene, content and inventory state. The intact preview stops before destructive exercises and remains in the temporary save scope. The full driver has a bounded 20-minute deadline, with a 21-minute editor watchdog.

Reports live under `Docs/Verification/MorrowfastScene/`, with raw EditMode output, `native-audit.json`, `native-preview.json`, screenshots, executed command counts, final zone, isolated save-root/GameID evidence, per-check failures and bounded profiler records. Screenshots and the report from a failed run are retained when they explain a correction. A summary cannot say all native checks passed when a check was skipped or only a browser simulation ran.

**Can verify through script observation:** scene/owner identities, native menus and selected targets, actual player cells, collision, turn energy, inventory/currency/quest deltas, emitted message serials, save roots, active/cached state, renderer activation and measured profiler samples.

**Requires rendered visual review:** natural placement, matching scale/palette, roof cutaway readability, actor/front-wall sorting, contact quality, FOV behavior and convincing exposed surfaces. EditMode and raster checks do not settle these questions. Editor timing includes UI, save/load, capture and audit overhead; it is not a standalone build benchmark.

## Living implementation log

- Initial source sweep completed. The source has an open arch, not closable gate leaves; the Felling transform and passability approximation cannot be copied unchanged. Native audit input and save isolation are reused as proven infrastructure.
- Initial integration/adversarial tests were authored before gameplay production. The coordinating Unity operator captured a **compile-prerequisite RED**: the main assembly could not resolve the not-yet-implemented `MorrowfastSceneRuntime`, so the test assembly was not executed at that point. This is not misreported as failing test assertions.
- Initial native EditMode execution reached the real test runner after implementation. A roof collision test exposed a missing positive fixture precondition: the runtime correctly refuses externally lifting a closed, unentered room. The fixture now opens the doors, and a separate countercheck verifies the closed-room refusal. Reverification and live native screenshots remain pending.
- The first targeted green run is retained as [424-test XML](Verification/Morrowfast/native-424-green.xml): 424 passed, no failures/skips/inconclusive results, 36.129 seconds. It includes 143 Morrowfast cases and 281 existing-system regressions. This evidence predates the subsequent live-audit corrections below.
- The [first native audit](Verification/MorrowfastScene/native-audit-first-red.json) passed all five door/interior cycles and manual roof checks, then stopped after 43 exact owner examinations and 421 native steps. Read-only live diagnosis found the tortoise had entered the guesthouse doorway at `(32,12)`, trapping the player at `(28,12)`. Habitat movement receives a production restriction; the driver separately gains bounded real waiting only when ignoring a living blocker reveals an otherwise valid route. Permanent terrain blockage still fails.
- Live review also identified a native input routing defect: redirecting every footprint contact to its large owner hid the stove/crate pair sharing a cell. [Two overlapping-owner tests failed](Verification/Morrowfast/native-overlap-input-red.xml) while the prior three interaction cases passed. The corrected input preserves ordinary individual/pile selection for every real non-terrain occupant, including ordinary loose loot; only bare footprint contacts redirect. A further loose-Tepuibone countercheck was authored before this correction. Native and automated reruns are pending for these changes.
