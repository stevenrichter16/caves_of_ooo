CONTEXT Participating Parts — what each actor needs 3 actors ▼

A melee swing only works if every actor has the right Parts attached. Missing a required Part causes the swing to bail early (see Phase 1 reachability gates). Optional Parts add behavior without breaking the swing — that's how skills, mutations, and weapon-mods extend combat without touching Combat.cs.

ATK

Attacker

  • Combatorchestrates the swing (Priority=INTEGRAL=90000)
  • Bodyprovides body parts holding weapons
  • PhysicsCurrentCell + CheckFrozen gate (AttackDirection bails without it)
  • StatisticsStrength/Agility/Ego for damage; Hitpoints
  • Skillsto-hit, pen, crit modifiers via GetMeleeAttacks / GetMeleePenetration handlers
  • Mutationsadd intrinsic attacks via GetMeleeAttacksEvent (Stinger, claws, etc.)
  • ActivatedAbilitiescharge attacks, special-attack abilities
  • BrainAI source for non-player attackers
DEF

Defender

  • Physicsconsumes "TakeDamage", runs the Phase-10 typed-event cascade
  • CombatDV/AV calc, defender-side event handlers
  • StatisticsHitpoints, AV, DV, MA (MentalArmor)
  • Rendermessage-log color, hit/death animations
  • Bodyrequired for armor slots and dismember effects
  • Inventory + ArmorAV bonus via GetDefenderHitDice handlers
  • Brainconsumes Phase-12 AIMessage("Attacked") to react
  • EffectRackstatus effects (Bleeding, Stunned) modify DV/pen/damage
WPN

Weapon

  • MeleeWeaponBaseDamage, Stat, PenBonus, Skill, Attributes — bail at Combat.cs:901 without it
  • Rendervisual + hit-animation prefab keys
  • VibroWeaponphasing through AV in Phase 8
  • VampiricWeaponheals attacker on AttackerDealtDamage in Phase 10
  • PoisonMelee / DiseaseMeleestatus proc via WeaponHit handler
  • AfferentWeaponattribute-stat damage scaling
  • BreakableInMeleedurability decay via WeaponAfterDamage

UPSTREAM Trigger paths — how does BeginAttack get called? 4 entry routes ▼

Four distinct call sites can initiate a melee swing. All converge on Combat.AttackDirection or Combat.AttackObject, which call BeginAttack + PerformMeleeAttack in sequence. AttackDirection resolves a direction string to a cell; AttackObject takes the target directly.

▸ Player movement-into-enemy
Pressing a movement key into a hostile cell. KeyMap maps the keystroke to a movement intent; the action queue resolves it through XRLCore. If the destination cell has a combat target, the move becomes an attack.
XRL.UI/KeyMap.cs → XRL.Core/XRLCore.cs → Combat.AttackDirection
▸ AI Kill goal
The Brain's goal stack pushes a Kill goal when a hostile is in range. The goal handler picks the target and calls AttackObject directly — bypassing direction resolution since the target is known.
XRL.World/Brain.cs → XRL.World.AI.GoalHandlers/Kill.cs → Combat.AttackObject
▸ AutoAct continuation
Player's autoexplore or auto-attack repeats the prior action. If the previous step was a swing and the target is still in the same direction, AutoAct re-fires AttackDirection without further player input.
XRL.World.Capabilities/AutoAct.cs → Combat.AttackDirection
▸ Skill / ability triggers
Skill-driven attacks (Tactics_Charge runs the charge animation then swings, Cudgel_Conk fires a special attack). These call AttackObject with custom Properties to flag the swing as Auto/Critical/etc.
XRL.World.Parts.Skill/*.cs (e.g., Tactics_Charge.cs)

Pre-event gates that fire BEFORE Phase 0: Attacker.Physics == null (bail) · Attacker.CheckFrozen() (bail if frozen-solid) · cellFromDirection != null (bail if no cell that way) · Cell.GetCombatTarget() (bail if no valid combat target in the cell — also handles flight/phase compat). These are non-eventful, return-false bails inside AttackDirection / AttackCell at Combat.cs:844-890.

DOWNSTREAM Aftermath — what happens after PerformMeleeAttack returns turn loop + conditional death ▼

After Phase 12 (UseEnergy + AIMessage) the swing function returns. Control flows back through AttackObject/AttackCell to the caller. Two paths run in parallel: the defender's fate (survived / died) and the attacker's turn-loop progression.

DEF

Defender survived

  • Brainreads AIMessage("Attacked"), updates threat list, may switch to combat goal
  • EffectRackBleeding/Burning ticks scheduled for next turn
  • HP regennatural healing resumes on subsequent turns
  • Faction-repif attacker was friendly, defender's faction may flip hostile
PHYS

Defender died (HP ≤ 0)

  • Die()GameObject.cs:14491 · Dying flag prevents re-entrance
  • BeforeDieEvent.CheckCANCELLABLE — death-prevent abilities (Force Wall, save-from-death mutations) return false
  • AfterDieEvent.Sendpost-death notification (achievements, kill-tracking)
  • StopMovingclears any pending paths
  • Particle VFXif Options.UseParticleVFX, render death animation
  • Inventory dropcorpse spawned with loot
  • Faction-rep updatekiller's faction takes a hit against defender's faction
  • XP grantif killer is player-led
ATK

Turn-loop continuation

  • Energy spentAttacker.Energy.Value -= 1000 (or 750 with ShortBlades_Expertise)
  • ActionManagerif Energy ≤ 0, actor's turn ends; otherwise more actions allowed
  • Next actoraction queue advances to the entity with highest pending energy
  • AutoActif player was auto-acting, may re-fire AttackDirection next iteration
  • RenderZoneRenderer marks affected cells dirty; UI redraws

Death cascade entry: Physics.cs:4175 checks CurrentHP ≤ 0 after damage application, Physics.cs:4233 calls ParentObject.Die(LastDamagedBy, ..., Weapon, Projectile). The Dying guard at GameObject.cs:14494 prevents re-entrance — important when a damage handler triggers cascading effects (e.g., explosive death) that try to call Die again on the same actor.

PARALLELS Related combat flows — same pattern, different vertical 3 sibling systems ▼

The melee-swing pattern (event-cascade with cancellable Before*/Check + post-fact Send) is reused across all combat verticals. Each entry point owns its swing orchestration in Combat.cs, but every one converges on Physics.TakeDamage for the actual HP subtraction. Reading any one of these traces unlocks ~80% of the other three.
