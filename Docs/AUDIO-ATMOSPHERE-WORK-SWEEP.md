## Recommendation 1 — committed hand work

Smallest useful core: **RepairablePart + FieldHarvestService + CropYieldService**, using their existing AfterCommit seams and one optional presentation receipt. Add ForgeWeaponCommand only when an appropriate anvil/tool recording is approved; keep it a separate bounded extension if necessary. Do not hook both service and command for the same action.

Suggested receipt shape: work kind, actor, original zone, copied source cell and material/family; an exact source reference where it remains meaningful. The emission comes only from the authoritative successful transaction. The router checks current listener graph/actor and the selected source cell, and uses the existing bounded SFX pool. It must not infer success from a visible animation, menu key, message string, number of removed materials or ItemAdded callback. An explicit player action may finish while its own action menu hides the world; decide and test that player-feedback rule separately from passive town work. Hidden remote NPC actions must never become directional hints.

For cultivated harvest, retain a transaction-bound contact receipt instead of a generic dead/removed-source fallback. The source is expected to disappear because that exact successful harvest removed it. A rejected transaction, automatic maturity, a source moved by a callback before completion, wrong saved graph and arbitrary later source removal do not gain this exception. No pending sound state is serialized; loading a repaired site or spent field cannot replay the work.

### Existing recordings and gaps

- `Sfx/use.ogg` is **cloth1**; `Sfx/pickup.ogg` is **handleSmallLeather**; `Sfx/equip.ogg` is **beltHandle1**. These can honestly support wrapping, rope/leather handling and bundled produce, at restrained gain. They are not a recorded plant-pluck or a forge.
- `Places/wood_creak_01/02.ogg` can provide one quiet wooden-brace settling accent. Do not start a creak loop when repair merely restores a flag.
- `Places/stone_tick_01/02.ogg` are **impactMining**. Appropriate for explicit hard stone tool contact, not wet clay seam packing or every repair composition.
- None of the current 53 recordings is a clean anvil hammer, wood joinery tap, grain/leaf pull, scrape/stir or cooking-utensil recording. Four combat-hit families are designed body-contact textures and must not be relabeled as hammering.
- If extra material distinction is selected, request paired short CC0/original anvil strikes, wood-tool taps and crop/bundle rustles with provenance. Keep the original assets intact. A low-gain existing handling sound is an honest interim choice; do not claim new acoustic specificity it cannot provide.

## Recommendation 2 — an actually working wayside kitchen

This supplies genuine occupied-town detail without inventing NPC schedules. Add a **side-effect-free** `KitchenBatchPart.IsAudibleWorkCurrent(Zone zone, int tick)` (name is a proposal) reusing existing `Bound`, `ValidJob`, `InputsCurrent`, `LiveStructure` and `StaffAvailable(zone, Commissioner)` validators. Require nonnegative current tick in `[StartTick, DueTick)`, a living correctly bound cook within the existing two-cell range, and correct currently visible pan/worker. It must not call `Reconcile`, create a meal, charge currency, advance time or scan cached world zones. Current private validators allocate small arrays/LINQ in places; do not blindly call them per frame. Evaluate on the existing bounded context/turn refresh, and retain only enough exact witnesses for cheap invalidation between sparse detail emissions.

One sparse preparation texture with silence between gestures is enough. Start only from an actually committed Working job; Ready, cancellation, stolen ingredients, broken pan, removed/moved/dead/hostile cook, hidden world and changed save graph must stop it. Recheck near the emission and retain source ownership through its short tail using the existing soundscape lifecycle. A source discovered before commission must not be mistakenly carried into Working; completed jobs found on arrival must not replay past work. No forge loop, generic crowd or pan sizzling inferred from stored heat alone.

Current 53 assets provide hearth crackle only when its own actual fire predicate qualifies, and cloth/leather handling for a finished parcel. They provide no recognizable active food-preparation utensil/scrape texture. Recommend two short licensed/original soft bowl/utensil/leaf-wrap gestures before claiming audible cook work; preserve the existing fire source separately. If no suitable asset is selected, the honest smaller change is one completed parcel handling receipt at `KitchenBatchReady` AfterCommit, not a fake cooking loop.

Tests extend `ConnectedKitchenTests`, `ConnectedKitchenAdversarialTests`, `ConnectedKitchenCallbackLifecycleReviewTests`, `ConnectedKitchenCallbackExceptionReviewTests`, and `WorldAudioPlaceAdversarialTests` through a new focused work fixture. Pair a paid valid job with Idle, unpaid, Ready, due tick, malformed ordinal/times, replaced exact input, lost escrow, replaced worker, distant/hostile/dead/hidden cook and broken station. Assert zero simulation mutations from every audio query, no fresh source scan while idle and the existing 16-source cap. Round-trip a Working save without duplicate voices; a completed save must not replay its preparation or ready cue.

Live iteration route: enter the authored wayside kitchen through normal world navigation; repair the pan and obtain ingredients/currency through available actions, commission from its actual menu, observe the work sound while nearby, step away/return, then wait to the real due tick and verify the actual meal publication and cessation. Capture fresh per-iteration audio/source evidence and restore isolated save/preferences. This is a different live run from recommendation 1; if route prerequisites cannot be met honestly, report that blocker and do not label the iteration live-tested.

Saved implementation prompt proposal:

Add a pure authority query using the existing KitchenBatchPart rules, a sparse source-bound preparation texture and immediate source invalidation. Keep queries free of simulation changes, no per-frame world scan and no phantom town or forge loops. Execute RED and native counterchecks, then run and retain a fresh actual commission/wait/meal Play route for this iteration before proceeding.
