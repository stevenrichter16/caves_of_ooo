# Sodden performance cold-eye review — 2026-10-09

Read-only comparison of current staged renderer changes against `HEAD`. No Unity execution or source edits. The reported ~24 ms mean / ~63 ms p95 is concerning, but does not yet establish a new-art regression.

## What the recorded number measures

`Assets/Scripts/Scenarios/Custom/SpreadDiscoveryNativePlayer.Profile.cs:12,29-37,59-68` records `COO.ZoneRenderer.LateUpdate`, Main Thread and global GC. The first is **one CPU component marker**, not GPU frame cost or the entire native presenter. `SpawnRing3DPresenter.LateUpdate` is a separate Unity callback (`SpawnRing3DPresenter.cs:628`). Existing profile explicitly includes screenshots, audit IO, paced input, and AI. Its sampling arrays are allocated at start, while LINQ materialization/JSON observations occur at end. Do not attribute global GC to regional mesh rendering without a quiet window.

## Proven recurring additions, ranked for measurement

1. **New transient work on each dirty refresh.** `SpawnRing3DPresenter.cs:224,267-312` now enables `SpreadTransientVolumes` in authenticated Sodden. The preexisting implementation (`SpreadTransientVolumes.cs:31-60`) scans all zone entities to ask `TryGas`, scans written tile keys, revalidates existing views, then updates each current view. `SpreadTransientSource.cs:23-31` checks two region scopes, cell membership, several Parts and visibility before reaching `gas == null`; therefore ordinary nongas owners incur this work too. `TryTileSample` can run both surface-mark and elemental source checks (`Volumes:98-99`). The *algorithm* already shipped for Spread; its whole-zone workload is newly enabled for Sodden. This is a concrete dirty-refresh CPU addition, not evidence that it accounts for 24 ms. It also allocates small strings for live gas shape keys (`Volumes:116`) and actual coating/residue samples (`Source:69,78`). These are source/view proportional, not mesh-buffer allocations.

2. **Repeated scope authorization on ordinary rendering queries.** The new `SoddenPopulationArtRecipes.Refine:11` checks Sodden authority before testing whether the owner is Greatdew, so it runs for every owner resolved by `SpawnRing3DRecipes.Resolve:26`. Portable, humanoid, visitor and native terrain paths also gain exact Sodden checks. `PresentationVisible` now reaches an extra scope check (`SpawnRing3DPresenter.cs:77-84`) through per-owner/per-cell claims (`603-619`) as well as actor refresh (`294`). The check performs weak-table/current-manager/cache/map/area-policy lookups (`SoddenPresentationScope.cs:18-43`); it caches address parsing, so repeated `FromZoneID`/string splitting is **not** occurring. `AreaCompositionScope.Allows:63` still traverses the existing finite candidate-policy predicates. This is repeated CPU work, with no proven per-call managed allocation. Never replace it with an indefinitely cached boolean: current-world/profile/cache mutation is intentionally tested.

3. **Additional material batch only when geometry really changes.** `SpawnRing3DGroundPatches.cs:144-195` retains the existing marked-patch fingerprint path. Null dirty sets check all fingerprints; equal fingerprints do not rebuild meshes. The new Sodden bucket creates one extra combined mesh/material group only on changed patches (`198-255`), with existing `CombineMeshes(pieces.ToArray())` copying (`327-337`). There is no new per-frame mesh read or unconditional per-frame rebuild. Denser replacement geometry may increase rebuild/submit/GPU cost; measure patch revisions/vertex counts and actual GPU timing before blaming the fingerprint loop. `nativeStyles?.ForOwner` remains null outside gameplay-Spread, except legitimate Sumphold overlap.

## Bind-only costs / rejected hot-path hypotheses

- `SoddenNativeArtLibrary.Validate:90-155` really copies `mesh.vertices`, `mesh.uv`, `mesh.normals` for all85 entries, but callers are `VoxelWorldPresentation` construction (`119-138`) and `SpawnRing3DPresenter.Bind:168-201`. Same-zone `Bind` returns early (`98-99`); `Find:56-60` uses the built dictionary. Validating twice is redundant cost at region bind, **not every frame**. Current kit has1,529 boxes /36,696 vertices, implying1,174,272 bytes of these copied channels per Validate, about2.35 MB over both calls, excluding array/header/string/other-library costs. This can contribute to transition GC/spikes.
- Approved-style catalog creation and shared library validation (`SpreadBiomeStyleEvidence:92-121`) are bind-only. Palette proof reads use reused lists/property blocks (`126-137`), not new full mesh buffers.
- Geometry replacement, actor bounds fitting, and worn-equipment initialization are at instance creation/state changes. No new `Update` that rebuilds Sodden assets, no runtime modeling, no uncached new `Resources.Load` in the normal frame loop was found.
