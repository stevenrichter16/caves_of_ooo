## Rendering and input contracts

- The base and background structures use sorting order 3. Foreground roots and mutable props use actor body order 6, with compatible foot depth. Cursor, effects and UI keep their existing orders.
- Environment claims suppress authored terrain and scene owners. Unmapped live actors/items retain the ordinary renderer or glyph fallback above the native ground.
- Look-mode clicks use source alpha and choose the actual owner. Movement, throwing and spell targeting retain geometric cell picking. Existing reach checks guard acting commands.
- A 48×32 point-filtered linear texture stores current/remembered/unexplored visibility. It updates on existing full or cell invalidations. Source alpha and overlap coverage are cached on bind. Each fixed facade column uses up to four local observation samples; ground and mutable objects retain direct cell ownership.
- Scene framing fits 48×32 world units against the actual HUD-excluded viewport. Sprite-mode off, unavailable art or departure restores ordinary camera bounds and zoom.
- Pause hides the native views. Zone changes destroy only owned runtime objects/materials/textures; imported shared resources remain owned by Unity. Invalid assets produce a visible terrain-fallback message and make no scene claims.

## Viewport history regression

The later third-run harvest capture exposed a defect that the intact initial capture did not: after exterior tracking or a modal view, old pixels remained outside the narrower map camera rectangle. The scene still occupied the correct bounds. The excluded strips simply had no camera clearing their old color. Root recorded the native GPU failure in `letterbox-gpu-red.json`.

The dedicated Unity GPU regression independently reproduced this using a magenta render-target sentinel and actual URP single-camera render requests. Before production, job `278826b2f5a1412eb8303fae7004460b` found 6,040 uncleared margin pixels on a 640×360 target and 105,560 on a 640×640 target. Two lifecycle checks also failed because no clear pass existed. Raw evidence is in `letterbox-clear-focused-red.json`.

`CameraFollow` now owns one reusable empty camera that clears the original map rectangle to black before the main scene camera draws. It culls all objects, disables shadows/postprocessing and additional color/depth texture requirements, and shares the existing output target; normal play allocates no extra scene render texture. Exterior tracking, sprite fallback, fullscreen UI and disabled owners turn it off. Centered map popups retain it underneath their overlay. Cleanup destroys only the owned camera.

Job `bd183555595b44c9bfa42be1859ce9c6` passed 53 tests with zero failures or skips, including both GPU readbacks, source presentation, ordinary camera/HUD behavior and camera cleanup regressions. The GPU tests require black margins while preserving sentinel pixels in the sidebar and hotbar regions. One intermediate fixture correction explicitly invoked the cleanup body because `CameraFollow` does not run its native lifecycle in EditMode; runtime lifecycle dispatch remains part of the native audit. JSON and full NUnit XML are saved as `letterbox-clear-focused-green.*`. The final native screenshot sequence remains root's independent end-to-end verification.
