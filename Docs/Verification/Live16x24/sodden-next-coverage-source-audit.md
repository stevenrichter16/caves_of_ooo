## Decision

After accepting the current district material packet, extend its **same exact-owner/state static materials to ordinary Sodden wilderness**. Reuse MirePool, Duckboard, PeatBank, DeadTree, Reeds and ordinary Grass; retain all custom-identity, custody, footprint, part-ownership, fog, current-graph and hazard controls. Do not add scenery merely because a screenshot still has fallback glyphs. Do not widen global `FlatPixelGreyboxCatalog.IsAdmitted` or mark a whole biome complete.

This covers the structural vocabulary of all six ordinary formations with the smallest new art cost. DrownedCopse still needs a separate, explicitly scoped **plain shallow-water** presentation: its water is tile state, not a MirePool owner. The follow-on content packet should prioritize the actual visible frogs/Greatdew and bog-taken body, plus encountered shared props, while the regional terrain queue advances to Beating. Avoid spending another open-ended pass on one district's furniture or subtle animation.

## What appears sparse in source, and whether generation should change

**No actual placement defect is established by this read-only audit.** Source guarantees and risks can prioritize a capture; they do not prove the user's view is too bare. Do not ship a generation change solely from these observations.

1. **Materials exist but lack native rendering:** all six formations already supply coherent major objects. This is primarily sprite routing/coverage. Accept the shared material kit first. Missing frogs, bodies, containers, herbs, hazards and structural landmarks are also rendering gaps when those owners are present; increasing their counts would not solve that problem.
2. **Wide quiet approaches and outer rims:** composition reserves all four approximately three-cell-wide routes to a central dry island (`SoddenCompositionPlan.cs:55-69,130-141`) and exempts a two-cell outer rim (`:81`). The builder reserves both wet cells and approaches (`SoddenCompositionBuilder.cs:34`). Later population, hazards, containers and haulables respect these reservations. This can produce long grass-only sightlines, but it is intentional safe travel. First make existing Grass variation and adjacent clusters read well. Only if actual normal-zoom entry/interior/boundary views remain monotonous should a separate generation slice alter the *shoulders* or attach coherent dry-side clusters, preserving the full route, stair and tactical envelope. Do not pepper the reserved path with collision or hazards.
3. **No landmark in a sampled chunk:** optional stamps have20/15/30% attempts, a cap of2, and at most80 candidate anchors; reserved/liquid/stair/solid footprints are rejected (`LandmarkBuilder.cs:1207-1209,1240-1250,1285-1328`). A landmark-free chunk is a valid branch. If repeated actual scenes reveal dead stretches, distinguish a legitimate failed roll from rolled-but-unplaceable topology. A later bounded generation change could select eligible dry-side anchors coherently; do not convert every optional landmark to guaranteed or bulldoze the wetland.
4. **Repetition at shores/bank rows:** the initial atlas intentionally has limited static variation. If existing pools/banks look tiled, improve a named native material/edge defect using actual owners and disclosed neighbors. That is generally a sprite composition issue, not a need to spawn more reeds or walls.
5. **DrownedCopse still reads as grass with blue wave markers:** this is the likely missing *water presentation* family. The actual permanent water already exists (`SoddenCompositionBuilder.cs:36`). Replacing it with spawned MirePool would change chemistry/exposure and be wrong. A future water layer must derive from current disclosed tile state, preserve thermal/charge/residue/mist priority and not invent a pool owner for Examine.
6. **Formation identity lost because foliage/water overlap:** current composition intentionally converts every wet non-copse cell into MirePool after reed decisions (`:126-128`). Do not densify by stacking reeds on hazardous pools merely to hide gaps. Diagnose selected owner, actual coating and substrate together.
7. **Real placement failures requiring code, if observed:** disconnected/blocked approaches, landmarks placed on reserved paths, source objects hidden by wrong layering, or a systematic lack of valid optional anchors despite meaningful remaining dry space. Address the exact failing seed/graph under RED/GREEN, counter-check the unbroken neighbor and preserve saved graphs. Existing source tests already cover all-open-cell reachability and resident habitat; none of those tests are a visual fullness verdict.

Existing tests inspected, not run here: `SoddenCompositionAdversarialTests.cs:68-93` routes ordinary/district/merchant-camp paths distinctly; `:181-227` checks connectivity/residents; `:282-312` uses real complete pipelines and all four safe approaches. `SoddenCompositionReviewTests.cs:15-43` exercises resident-inclusive pockets. Reuse those invariants if generation truly changes, rather than building an unrelated new harness.
