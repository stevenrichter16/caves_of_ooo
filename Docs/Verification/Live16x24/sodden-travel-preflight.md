## Owner, state and ground policy

Reuse the current owner selector, `Owned<T>` pattern, single-cell footprint guard, exact-resource failure handling and ownership-only disposal already used by Sill/KitchenBrine. Keep code bounded to this adapter and a short catalog routing addition; do not refactor all old catalogs to a generic policy engine.

- Common foreground: visible/explored current cell; selected actual owner; one owned Render/Physics; world custody; non-takeable; no Item/Creature/Player role; no custom VisualID/VisualVariant; positive valid stack if present; single-cell current footprint only. Exact glyph/variant role must match the canonical family. Reject foreign or duplicated essential semantic parts rather than accepting same-name data. Native render passes never fire simulation events.
- Duckboard: exact `Duckboard`, Terrain, Wood, non-solid, `=`, live positive-HP Destructible. Actual N1,E2,S4,W8 board masks use only current selected visible matching neighbors, never diagonal/cell-name hints; covered or unseen neighbors cap the visual route. Do not let broken/gone material persist. This connection policy matches Sill/Hedge disclosure behavior and avoids reading unseen state.
- PeatBank: exact `PeatBank`, Terrain/Wall/Solid, physical solid, Peat, `#`, live positive-HP Destructible. Nonlethal damage can keep its silhouette; destroy removes it. No PeatBog alias.
- DeadTree: exact `DeadTree`, Terrain/Vegetation/Solid, physical solid, Wood, `T`, live positive-HP Destructible. No live Tree canopy/fruit.
- Reeds: exact `Reeds`, Terrain/Vegetation, `|` with canonical `GlyphVariants="|!"`, non-solid, non-takeable, no foreign source/service/harvest meaning. Use existing frames3/4; never globally route every `|` or arbitrary ordinary vegetation through opening art.
- MirePool: exact `MirePool`, Terrain, Peat, owned LiquidPool `bog-mire`, effective source `bog-mire`, non-solid, `~`, finite thermal state above freeze, live positive-HP Destructible, no unsupported glyph variants. Source's original `Coating="water"` is valid once actual registry resolves its identity. Require live sole bog-mire coating for neutral native liquid surface; mixed/unknown/ice layers keep truthful fallback unless specifically authored later. Source stock and tile coating are distinct. Initial `Zone.AddEntity` already projects permanent bog-mire independent of Volume; source seeding renews the same layer. Removing the last ordinary same-liquid pool unprojects its unowned coating; another same-liquid pool preserves it. Frozen/electrified/burning owner effects need either proven native state feedback or fallback, since white native pixels ignore dynamic Render tint (`ZoneRenderer.FlatPixelPaint.cs:35–41`).
- Ground: only current visible exact ordinary Grass / StoneFloor with canonical `.` + `...,.'\x60`, correct role/owned Render/Physics and no custom identity. Actual StoneFloor wins over Grass if both qualify; ambiguous duplicates fail closed. Do not draw dry material over cultivated soil, crop/field owner, marker, real Duckboard/pool/other terrain, trigger or ANY nonempty tile-state record. Use Sill's visible/current-owner correction before evaluating a competing owner. A covering creature/item alone does not erase the qualified floor. Do not copy Sill's scope to authorize unrelated settlement families.
- Reader: minimum safe policy is same currently selected visible subject using the same frame/role resolver. Do not grant hidden/carried/covered subjects a world portrait through a second weaker identity path. A later lower-subject reader can be added only with the document authority and full current-placement gate already demonstrated by KitchenBrine.
- Missing/malformed native texture: retain fallback for that group; do not reload Resources behind an explicit null injection. Borrowed atlas assets are never mutated/disposed. Cached Tile/Sprite objects alone are disposed idempotently. Keep base/native sources reversible.

## Liquid-overlay decision before runtime implementation

`RepresentedBrine` means sole-live BRINE, not all liquids, and `GroundKind.Water` can suppress water only. Never set either for mire. Keeping the current blue wave untouched is the simplest initial implementation but remains an existing style/readability defect; disclose that limitation instead of claiming hazards are solved.

If actual baseline shows the expected blue waves dominating native mire, the bounded preferred correction is an independent **exact mire surface representation** flag, set only when the current submitted visible native MirePool frame actually represents the sole-live `bog-mire` coating. Add a default-false parameter alongside the existing brine flag (or a similarly small explicit field), not a general liquid-render framework. Suppress only the duplicate mire wave, allowing existing charge/heat/cold priority to reach the next branch; preserve oil/mixtures/unknown/ice/residue/veil-mist logic. For Volume0, suppress only if the approved depleted frame explicitly represents a still-wet mire film; otherwise retain fallback and the wave. Under an actor, missing atlas, fog, stale graph or refused native owner the flag must be false. This requires real submitted-paint tests below. No mechanics or liquid source stock changes belong in this packet.
