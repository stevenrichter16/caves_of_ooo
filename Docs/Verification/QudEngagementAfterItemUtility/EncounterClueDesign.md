# A claimed cache and a remembered expedition

Status: **source-verified design only**, 2026-10-08. No gameplay edits or runtime verification accompany this document. Implement after the Sodden art release gate. This narrows recommendation 2 in [the engagement roadmap](../../QUD-ENGAGEMENT-AFTER-ITEM-UTILITY.md); it does not claim that the current exploration system lacks ecology, multi-system encounters, equipment destinations or travel notes.

## Prompts used

**Brainstorming:** Find one pairing of current ordinary-world mechanics which changes an actual decision without increasing the number of enemies or rewards. Verify exact generation timing, sources, finite stock and current AI. Contrast two player approaches. Reject pairings which merely add a second fight, require mutually exclusive terrain sources, or conceal important rules. Find one existing component whose practical role can motivate a later expedition.

**Design:** Turn the selected pairing and one historical clue into two independently shippable milestones. Specify bounded selection, shared ownership, useful geometry, failure and callback behavior, saved-world policy, player-facing evidence and native red/green/counter-checks. Prefer a small specific compositor over a general encounter framework. Distinguish a reported source from knowledge of its present inventory.

**Implementation:** Re-read the authorities below, update this document for any drift, then write and run native failing tests before production. Deliver the claimed-cache compositor first, the instance-specific note/one existing component lead second. Reuse existing models, AI, inventory and crafting. Exercise a real paid route, a peaceful bypass and depleted saved revisit. Fix significant review findings; record cosmetic or playtest limitations without endless polishing. Keep the living design and evidence with each implementation commit.

## Milestone 1 — claimed supplies beside a usable bypass

The existing warning gives the player time to withdraw. A prepared player can use cover, a distraction or an actual supply to create room; an aggressive player can fight. The crate remains whatever ordinary world generation rolled. Killing the defender does not conjure a reward. This makes the current territory rule relevant to a decision rather than adding another adversary.

## Risks and stop conditions

- **Yellow / atomicity:** two independently successful helper calls are not a combined transaction. The single final-commit boundary is required before this pilot ships.
- **Yellow / misleading reward:** generic cache tables differ by tier; a useful destination clue must not manufacture present-stock knowledge or a component reward.
- **Yellow / false affordance:** safe-edge inventory access can make the claimed cache irrelevant. Assert actual interaction cells, not just a decorative rectangle around its center.
- **Blue / cue readability:** first reuse current terrain, marker, warning and container silhouettes. If native play shows the watched area cannot be inferred, add a small truthful environmental mark backed by that exact territory owner; no persistent objective arrow or minimap reward icon.
- **Playtest / surprise:** stop after these two milestones and compare actual approaches. If every route is still “kill the same guard,” revise placement and reward accessibility before adding pair variants or more regions.

No production change, new art, runtime test count or completion claim is made here. Native RED, implementation, review, Play evidence and living-doc updates remain work for the ensuing milestones.

### Proposed exact API and wire boundary

Keep `SpreadDiscoveryNotes.Prefix`, the old internal `Record` type and old `Remember(Entity, Record)` / public `Read(Entity)` as v1 compatibility. Extend that same record with `string WorldKey, Subject`. Add:

```csharp
internal static bool Remember(Entity player, Record record, string currentWorldKey, out string refusal);
public static IReadOnlyList<string> Read(Entity player, string currentWorldKey);
```

This remains one small note provider. No registry, injected service, quest tracker or new world entity. The new reader first includes existing v1 notes unchanged, then at most32 valid current-world v2 records. A null/invalid key exposes only v1. It never generates a key, consults a speaker, calls `GetZone`, reads a remote container or repairs data. UI uses `WorldLocationContext.For(player.SpatialZone)` only after actual current cache membership; detached save tests pass a trusted restored key explicitly.

Proposed v2 prefix: `SpreadDiscoveryNote.v2:`. Exact key: prefix + WorldKey + `:` + DestinationZoneID + `:` + Family. Match every key component against its payload, require Version2 and canonical surface IDs, reuse existing bounded text rules, and cap serialized record length at4096. `Subject=place` is legal only for the eight existing families and their existing formation validation. `Family=sodden-peat-works`, `Subject=peat-mallet`, `DestinationZoneID=Overworld.17.7.0` and `Formation=SoddenDistrict` must occur together. Unknown subjects/families do not become arbitrary prose or reward claims.

Count all stored v2-prefixed properties toward the32-slot **write** cap, even corrupt/foreign rows; this prevents an accidental unbounded ledger and never silently deletes historical bytes. Updating the exact existing key at capacity is allowed. A new key returns `discovery_note_capacity`; the conversation reports that travel notes are full, separately from a stale offer. Readers skip corrupt/foreign records and do not let one malformed row suppress another valid record. If a malformed externally supplied save already contains more than32 valid rows, choose a deterministic bounded read order without rewriting it. V1's eight historical slots are outside the v2 cap. Duplicate v1 and v2 hearsay may both display; deduplication/migration is intentionally not part of this slice.

New modern dialogue records use Version2 and `context.Exploration.WorldKey`. Existing legacy reports in worlds without a valid saved key keep Version1 and their old write boundary; the new works lead is ineligible there anyway. Include family, destination and revision in the offered token, without accepting an arbitrary destination supplied by a caller. Revalidate the selected record against the actual current source context before writing. A current-world key alone does not authorize a report; the real conversation offer still does.
