### Proposed exact API and wire boundary

Keep `SpreadDiscoveryNotes.Prefix`, the old internal `Record` type and old `Remember(Entity, Record)` / public `Read(Entity)` as v1 compatibility. Extend that same record with `string WorldKey, Subject`. Add:

```csharp
internal static bool Remember(Entity player, Record record, string currentWorldKey, out string refusal);
public static IReadOnlyList<string> Read(Entity player, string currentWorldKey);
```

This remains one small note provider. No registry, injected service, quest tracker or new world entity. The new reader first includes existing v1 notes unchanged, then at most32 valid current-world v2 records. A null/invalid key exposes only v1. It never generates a key, consults a speaker, calls `GetZone`, reads a remote container or repairs data. UI uses `WorldLocationContext.For(player.SpatialZone)` only after actual current cache membership; detached save tests pass a trusted restored key explicitly.

Proposed v2 prefix: `SpreadDiscoveryNote.v2:`. Exact key: prefix + WorldKey + `:` + DestinationZoneID + `:` + Family. Unknown subjects/families do not become arbitrary prose or reward claims.

Readers skip corrupt/foreign records and do not let one malformed row suppress another valid record. If a malformed externally supplied save already contains more than32 valid rows, choose a deterministic bounded read order without rewriting it. V1's eight historical slots are outside the v2 cap.
