## Decision and exact proposed owner

Use one original `SpreadCookingCoals` owner, a residual-coal workspot with actual cooling stored heat, beside an existing finite FieldStrips grain source. It is an explicit new utility-source allowance, not a relocated town fire and not a disguised extra loot allowance. No food, vessel, stock, actor or salvage is created. The player harvests the real row, carries its existing Emberwheat, uses the inventory Cook command, and receives the separately approved ToastedEmberwheat. Passing by or returning to unavailable coals is valid.

The source is persistent when cold/spent. Save its exact Entity, Thermal, Fuel, Campfire flags and all aftermath through the existing accepted graph retention. Do not remove and rebuild it, reset its temperature on binding, relight on entry, or retrofit old cached/saved graphs. Later external heat/fire interactions remain normal material mechanics; there is no new refuel/ignite subsystem.

Author it directly as an appropriate PhysicalObject child, with exact Render/Examinable/Physics, Campfire, Thermal and Fuel parts. Do not inherit Campfire's LightSource/Flicker or silently use an authored town station. Proposed fields: `CampfirePart.FiniteCooking=true`, new `CampfirePart.AllowRest=false`; Temperature500, AmbientTemperature25, existing default decay0.02, HeatCapacity0.8, modest positive finite FuelMass. Exact initial Fuel fields and combustion threshold remain an explicit blueprint review decision, not inferred from mesh art. No Burning effect at creation, no Takeable/Harvestable/Container/Inventory, no reward or destruction drop. Prefer non-solid low coals on one bare dry cell, away from required port cells; the object itself then adds no movement bottleneck.

Cooking-ready is **not** identical to hot: readiness needs exact current owned Fuel/Thermal, positive finite FuelMass and Temperature at least `CookingService.MinimumFiniteCookingTemperature` (150). Fuel0 at500°C is still thermally hot but unavailable for cooking. A warm state below150 is not physically cold either; use “no longer hot enough to cook” rather than an untrue absolute cold claim. The model pair may distinguish sufficiently hot versus cooled coals by temperature alone, while reader/cooking permission separately explains fuel exhaustion or malformed source refusal.

`TorchLightPart.FindFire` already admits an adjacent actual Thermal.IsAflame source with usable fuel, without requiring Burning (`Assets/Scripts/Gameplay/Items/TorchLightPart.cs:186–198`). If the final coals use Temperature500/FlameTemperature300, lighting a real native torch is consequently available at first. Recommendation: preserve and document this existing heat interaction, rather than inventing an ignition threshold solely to suppress it. “Cooking-only” here excludes the Rest service; it is not a new universal prohibition on heat interactions. Root's exact blueprint review settles the authored threshold.

## Rest decision and save compatibility

Root approved a cooking-only workspot with no Rest service. Existing `CampfirePart` always offers Rest and next-band Rest (`Assets/Scripts/Gameplay/Settlements/CampfirePart.cs:25–52`), including at cold/finite sources. `RestSystem` fully heals and advances the pure world clock by60 or the next band, subject to nearby hostile checks (`RestSystem.cs:19–41,88–105`). That would otherwise make depleted coals a renewable recovery service, exceeding the intended finite cooking utility.

Add a narrow public saved `AllowRest=true` authored option later. Only new SpreadCookingCoals opts out. Both action gathering and direct InventoryAction execution must refuse rest when false, with no HP/clock/energy mutation. Do not key rest permission off heat/fuel, and do not change RestSystem. All current authored stations keep Rest when hot, cold, thermalless or exhausted.

The actual Part loader uses `Activator.CreateInstance(type)` at `Assets/Scripts/Gameplay/Save/SaveSystem.cs:1489–1495`, then loads saved fields; it does not use the constructor-bypassing Goal path. Default true should therefore survive an absent field, but this must be executed: old zero-field Campfire wire and the prior core one-field FiniteCooking wire both load AllowRest=true; a new false owner retains false through a full replacement graph save. This is an activation milestone test, not an amendment silently folded into the frozen core39 package.
