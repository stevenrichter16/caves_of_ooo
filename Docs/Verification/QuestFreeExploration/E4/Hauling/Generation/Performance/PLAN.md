# Bounded F9 cold-validation latency repair

Root authorized one narrow fifteen-minute investigation on 2026-09-28 after plain native seed1 committed GetZone samples remained 1.23–1.43s (cache <=0.007ms). No timer assertion, source budget, layout, frequency, callback validation boundary, whole-graph snapshot field or retained-state semantics changes.

Verified source: CaptureFinalState captures an OwnerSnapshot for each selected non-ground owner. Each invocation currently calls each snapshot's Matches, which scans every zone owner to require exactly one owner with that selected ID. Hauling validates a full non-ground packet before/after each bounded move. Proposed change: one fresh zone ID-count dictionary per CaptureFinalState invocation, passed only to those OwnerSnapshot.Matches calls; receipt paths retain their existing behavior. No count map survives a callback or validation invocation. Ordinal string equality and null IDs must retain the existing exact selected-ID semantics; unrelated duplicate IDs must not become a new rejection.

Before production: run paired tests for duplicate selected IDs added/removed between proof calls, same text in distinct string instances, selected ID mutation/restoration, unrelated duplicate IDs, selected movement/restoration, unrelated movement, null selected-ID semantics, and part/state mutation. These are behavior-preserving controls expected GREEN on baseline, not fabricated RED evidence. Native before/after timing establishes the performance improvement.
