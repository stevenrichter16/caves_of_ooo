### Concrete repeated work in source, without claiming measured attribution

1. `Builders/SpreadExplorationBuilder.cs:44–66` checks `IsCurrent` for every terrain hedge receipt before sorting/capping and creates two overlapping world-owner snapshots per attempted candidate. Its synchronous `Authority()` repeats the broad `others()` proof around callbacks.
2. `SpreadWildernessSituationPlan.cs:71–78,90–109` validates each captured owner by counting matching IDs across the entire zone. A proof with M owners in an N-owner zone therefore performs M full-zone scans in addition to graph comparison. Current native rows have roughly 2,200–2,300 owners and 150–215 raw hedges. Repeated exact-ID counting is a credible contributor. Reflection-based part/stat/goal snapshots and field comparisons (`:116–157`) add work. These are necessary proof semantics, not necessarily necessary repeated scans.
3. `SpreadExplorationPassage.cs:33–49,60–66,95–111` rebuilds geometry repeatedly during initial screening and callback/final validation. Each `Geometry` constructor scans all cells, labels components and floods border reachability (`Builders/SpreadWildernessSituationBuilder.cs:167–194`); each layout additionally performs cardinal BFS, an eight-direction lower-bound BFS, native `FindPath` and another component comparison. Revalidation after mutation/callbacks is intentional.

### Smallest safe optimization options, only if measured and approved later

- First inspect an entirely passage-local saving: the initial opened geometry at `SpreadExplorationPassage.cs:34–35` is immediately rebuilt inside the initial `Layout` call without intervening callbacks. Pass that same immutable geometry into initial screening only. Never carry it across authority/factory/placement/final-generation callbacks. Likewise, cheap exact eligibility may precede expensive receipt state validation, while selected candidates still receive the full proof before use. Expected savings are unmeasured and may be small.
- If owner-proof scans dominate, use a fresh ID-multiplicity census for **one proof invocation** and share it only among that invocation's owner checks. Do not introduce a zone-wide cache or trust EntityVersion: public ID/state can change inside callbacks without the assumed invalidation. This is a narrow existing proof-lane change, not a new receipt system; preserve duplicate-ID, replaced-owner, changed-stock/goal, foreign-backlink and late-callback controls. It affects shared validation, so defer unless the gain warrants the larger verification surface.
- Do not remove synchronous all-owner proof, final selected/support/removed-hedge proof, useful eight-direction detour, actual native path, or critical connectivity. Do not restore the disproved all-world equality promise across legitimate late naming.

A future paired check should use the same three seeds and exact selected addresses, alternating old/current implementations in one runtime, confirm identical accepted/refused owners, layout, stock and next RNG, and report allocation support honestly. The existing cold corpus is enough; no new benchmark framework is needed.

### Recommended first implementation contract

- One original hunter, one exact generated reedback prey, one finite hunt. Require both source allowances and both blueprints before replacing either roll. Missing content or source preserves the original rolled list and honestly refuses the family. Keep pets, civilians, player inventory, quest/protected sites, BitLocker and special lore actors outside this source path.
- Use a new small saved hunter role, admitted from Bored before generic hostility, with exact prey reference, explicit bounded phase/turn/last-seen state and one terminal spent/escaped state. Reuse the existing inline one-action native combat pattern (`SpreadTerritoryPart.cs:125–139`), not a new unbounded child-goal chain. Do not manually advance time or trigger two movement/attack actions in a scheduler turn.
- The prey recognizes only its actual current configured hunter as an additional threat. Do not write permanent PersonalEnemies merely to make predation work: that relation is bidirectional and overrides party alliance (`FactionManager.cs:203–228`). An actual attack may still produce normal hostility. Existing Calm/follow/work goals keep their scheduler precedence.
- Decide finite last-seen pursuit, start separation, player immediate-threat threshold, failed-path cap and terminal escape before tests. Make actual cover break useful; do not implement omniscient pursuit under a cover-themed description. No offscreen food-web simulation or forced winner.
- Feeding should initially consume at most the hunter's own exact unheld world corpse on one paid turn, with SourceID/KillerID proof (`CorpsePart.cs:192–202`), a saved spent state and callback-safe removal. If the native corpse roll produces none, finish without feeding. Player pickup/harvest or a different killer cancels feeding; never reach into player inventory. If instead the design wants harvest-then-eat, explicitly budget its item creation/overflow transaction—the existing player Harvest action is not a free corpse-consumption API.
- The current grazer corpse has an inherited sale value but no meat yield. If the chosen design adds RawMeat, make that a declared finite data/reward addition with a value budget. If feeding consumes the carcass, the player must be able to intervene beforehand; do not award both a consumed meal and an untouched full corpse by implication.
- Author a real natural weapon/anatomy and new original hunter art/strike/feeding states. Do not inherit an accidental unarmed fallback. Use the existing grazer body and honest flight, without inventing a second grazing-row allowance for the hunt.

Source files likely affected: `SpreadExplorationPopulationPolicy.cs`, `PopulationBuilder.cs`, existing receipt source lane, plan/catalog/composer, one scoped hunter part, a narrow grazer threat predicate, `BoredGoal.cs`, exact Objects child/weapon/corpse fields and scoped model bindings. Meaningful initial RED pairs: same-Beasts exact paired hunter induces healthy flight while ordinary allied beast does not; visible acquisition versus cover/lost-sight escape; actual one action/End/energy; player personal hostility versus uninvolved bypass; Calm and party interruption; removed/replaced/foreign prey; own kill versus other killer; real absent corpse; corpse carried/harvested during callback; save while pursuing and after escape/feed. Source tests retain actual producer revision, complete rolled budget, missing-child unchanged controls, fixed 1/64/1729 realization and critical-route/source ownership. Art gates require actual native attack/flight/feeding state and exact natural weapon.

The short native gate should witness a real generated pair acting before player provocation and a usable player bypass/interruption choice, plus honest escaped or native-killed aftermath and reload. A staged successful fight alone proves mechanics, not natural availability or the promised wandering decision. It is acceptable for a kill not to occur; forcing it would defeat the encounter contract.
