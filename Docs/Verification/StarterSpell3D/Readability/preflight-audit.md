## Agreed implementation contract

Root confirmed the smallest additional runtime data contract during this audit:

- `NativeSpellFxPiece.Emission` is a finite float in 0..1, `Glow` is a bool, and `VisualBounds` is a `NativeSpellFxBounds` enum with `CellSurface` and `AirborneDecoration`.
- `NativeSpellFxLibrary.Material` remains the required baseline Palette, preserving unchanged Rain and existing content. Add optional `LuminousMaterial` (`CavesOfOoo/Spell3D/Luminous`), required for a non-glow piece with positive emission, and optional `GlowMaterial` (`CavesOfOoo/Spell3D/SoftGlow`), required for a glow piece. Unused optional materials may be null. A malformed selected material must reject.
- Renderer selection is glow first, otherwise positive emission uses luminous, otherwise Palette. Always upload `_Emission`, including zero, so a reused view cannot inherit another piece's intensity. Glow requires positive emission plus a complete finite vertex-alpha gradient with minimum zero and maximum greater than zero.
- Exported mesh vertex colors use white RGB and bounded alpha falloff. Importer, actual mesh assets, validation and pooled rendering must carry this data consistently.
- Existing roles, anchors, outcome conditions, seven study IDs, 111 samples, 100fps and phase clocks remain. The new bounds field controls presentation treatment, not game occupancy or damage shape.
- Schedule cores before optional decoration, draw cores across accepted casts first, retain existing fixed budgets and valid caster-gesture semantics when no fragments match, and skip diagonal ground fit only for airborne decoration. Unknown/malformed entries still reject.

No save migration or gameplay change is needed. Treat the new export schema as a coherent source/export/import contract; do not silently accept an old export as the new approved art.

## First implementation cold-eye and lifecycle hypothesis

Root reported executable `R02b` RED: 71 cases, 6 passing and 65 failing, zero compiler errors. The runtime/library/shader drafts were then independently reviewed before first GREEN. Normal-path material selection/reset and disposal, essential-first scheduling and drawing, copied target-contact timing, and ground-only diagonal fitting matched the reproduced cases. The new shader includes resolve to the unchanged native visibility implementation; local emission still passes visibility clipping and normal depth testing. Transparent glow preserves destination alpha, which is compatible with the native composite consuming RGB. These are source-review findings, not GPU acceptance.

One concrete lifecycle defect was found in the draft renderer (`/tmp/NativeSpellFxRenderer.cs:68–71` and `:428–433`): `IsPrepared` detects a destroyed owned material, but `EnsureRoot` returns immediately for a surviving root before recreating that material. Consequently `Prepare` can return success while readiness remains false, and a subsequent view can receive a null material. The same structure pre-existed for Palette and now affects both added kinds. Suggested correction: detect interruption/cancel active native work, then ensure owned materials before returning for an existing root; preserve the existing view pool and borrowed assets.

At root's request, seven new hypotheses are frozen in `NativeSpellReadabilityLifecycleTests.cs` for central `R03`: three idle clone-loss/recovery cases, three active-loss/cancellation/recovery cases, and one unchanged-readiness control. Active cases exercise actual coordinator ordering, including readiness before native Update, and require the interrupted playback handle to become Cancelled. The control retains all three material identities, the readiness receipt and view pool. Meta GUID `91e7ef1ac6004ea6b73456d92402ee6c` is unique and only the GUID differs from the template. No production fix was made by the reviewer and the new tests remain unexecuted at this handoff.

`R03` subsequently reproduced all six lifecycle hypotheses, with the intact-readiness control passing; the original 33 independent adversarial cases were all GREEN. Root reported 67/85 overall, with the remaining failures comprising five pending-art cases, seven import-preflight guards and the six lifecycle cases. Root then installed the minimal material repair and import preflight. Independent source review found the repair addresses each reproduced path: `EnsureRoot` cancels active work before recreating missing owned clones, idle readiness recreates them before returning, and direct native Update cancels before attempting material assignment. `WorldFxCoordinator.PrepareNative` releases cancelled handles immediately after Prepare (`:137–138`); direct World.Play also releases old handles before registering a new one (`:154–168`). Pool/root and borrowed assets remain intact, and the existing material identity check rebinds recovered clones on the next actual draw. No new concrete defect was found. This is source acceptance only; central lifecycle GREEN and the next real GPU pass remain pending at this review handoff.

## Cross-feature correction: valid caster animation can have zero fragments

Before the next native pass, root found that blanket zero-fragment refusal violated an existing native contract. `Hydromancy_ConjureRain.cs:95–103` returns success even without crops, and `StarterSpell3DNativeAudit.cs:120` / `:243` requires that empty cast to retain the actual Rain native entry and caster gesture while drawing zero crop meshes. The older EditMode Rain test only checked no meshes (`NativeSpellFxRendererTests.cs:199–200`), so it did not catch the fallback-gesture regression.

Two paired probes, `SuccessfulActualRainKeepsItsImportedCasterGestureWithOnlyRealCropMeshes(false/true)`, brought the lifecycle file to nine cases. They execute the actual Rain skill, observe its real successful capture, and pass that capture to the coordinator with the actual imported Rain library. They require the correct native entry/CastClip, one full-duration caster hook, zero versus real CropCell geometry, normal completion before timeout, and no repeat gameplay watering.

`R06` produced 403/406 passing with zero compile errors: empty Rain failed as expected, the actual one-crop control passed, and the six material-loss cases were GREEN. Crucially, two unchanged `NativeSpellFxAdversarialTests.DefinedButIncompatibleAnchorRejectsInsteadOfSilentlyReinterpretingAuthoredCoordinates` positive controls (ConeCell/ReactionCell, `:224–246`) also failed: their corrected valid entries legitimately have no matching geometry, but still have native caster clips. This falsified the broader premise that zero fragments mean zero presentation work. The briefly proposed Rain-only exception is withdrawn.

Root's scope correction is to remove the newly introduced zero-fragment refusal and restore the original valid-entry behavior. This is a correction of our regression and a discarded hypothesis, not a newly discovered game bug or an enhancement to gameplay. No pre-existing baseline test or fixture is changed. Only the three new hypothesis cases are revised as `ValidFilteredEntryRetainsItsCasterGestureWithoutInventingGeometry`: they now observe a real coordinator caster hook, retained entry/CastClip, no geometry for filtered conditions, bounded completion, and a paired condition/path/Full-mode correction that produces geometry. The existing unknown/malformed refusal tests remain intact. No new policy flag or Rain-ID special case is required. These corrected cases are frozen for `R07`; the reviewer changed tests/docs only, and root owns removing the one-line refusal.
