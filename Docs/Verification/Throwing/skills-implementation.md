## Source verification corrections

- `SkillsPart.AddSkill` invokes the skill hook before registering its activated ability. Restoring persistent cooldown in `AddSkill` alone cannot update the new button. The existing registration path now synchronizes throwing debt after the ability exists.
- `ActivatedAbilitiesPart` receives arbitrary `EndTurn` broadcasts. The three throwing cooldowns instead tick through the existing genuine `TurnManager` owner-boundary guard, after generic callbacks, and persist while their skill is removed.
- `PickupCommand.ForRetrieval` requires a different recipient. Recovery needs a narrowly guarded self-recovery factory retaining the exact single unit without merging or equipping; canonical pickup permission/capacity/gathering logic remains shared.
- `MovementSystem.TryMoveChecked` runs entry callbacks before returning. A boolean return cannot report an entry exception after movement. The accepted relocation callback seals Recovery's inventory transaction before entry effects; subsequent failure is a paid partial action.
- Saved zone reconstruction uses raw cells plus `RebuildEntityCellsFromCells`, not live Add/Move notifications. Saved preparation can therefore retain its captured revision and is validated in `FinalizeLoad` after the complete graph exists.
- Source extraction legitimately changes item custody and quantity. A pure launch snapshot captures preparation before extraction; committed launch consumes it once. The earliest extraction undo can rebind the unchanged owner's paid preparation only after exact original source restoration. It never rewinds the global item generation.
- Incapacitation interruption uses committed `EffectApplied`, not a vetoable application query. Expired effects do not block actions.

## Implemented interfaces

`ThrowingRules.TryBeginSelection` returns a free explicit Measured/Driving/Recovery request for a currently owned and usable ability. Native input owns its modal state and pending scheduling debt. Direct gameplay APIs do not leave a global asynchronous save hold.

`Prepare` validates current actor/source/target/range, records one exact source, target, location, quantity, mutation revision and phase, and sets the six-turn debt. `CaptureLaunch` is pure; `CommitLaunch` consumes preparation once, establishes a serial and pays Driving debt when selected. Retry, target-specific penetration and post-proc surviving-contact push remain narrow hooks called by the canonical throw command.

`Recover` executes an inventory command: validate the exact marked adjacent unit, ordinary checked movement, irreversible step seal, then canonical identity-preserving pickup. Entry hazards/vetoes/capacity changes can produce a paid step without a recovered item. There is no auto-equip or teleport.

Actor `ThrowingStatePart` stores preparation, serial and three cooldown debts. Item `ThrownRecoveryPart` stores exact item/thrower/zone/coordinate/blueprint provenance plus a mutation generation. Successful relocation, custody, split/merge and Taken invalidate the relevant receipt; no marker is added to unrelated untouched items merely because they move.

Five real one-rank, one-SP nodes are authored in `Content/Data/Skills/Throwing.json`; runtime classes use the existing reflection registry and purchase system. No starter, teacher, manual, free supply, rank framework or Skimming node is added.

## Final retention decisions and limits

The decisions distinguish actual benefit, ordinary changed-condition reversal and the tested alternative. They do not turn a green command test into a retention vote or claim every confidence interval narrowed. The full +2 matrix stays historical, the +4 revision remains separate, and no fully earned five-node build is claimed.

- **Sure Grip — retain.** Exact eligible retry and actual natural retry use are observed; keeping the weapon for Puncture provides a real alternative preference. This does not establish a win-rate improvement in every matchup. The separate high-Agility cheap-dip matrix was not run, so dominance across those configurations is unverified.
- **Measured — retain +4 revision one.** AV4 scarce-projectile endpoint survival/health improves; low-armor Scrabbler favors Puncture. The modest armored objective differences remain imprecise under the exploratory interval check, and no successful extraction is credited to a living timeout. No universal dominance is observed in the tested conditions.
- **Driving — retain.** Destination gas improves actual enemy defeat, while pushing an enemy out of existing gas rescues it. At the selected 100 seeds the comparisons are 99 versus 23 defeats for useful placement, and 23 versus 75 for harmful displacement. Dry/wall/brace retain no-benefit cooldown controls; these arenas prove no player-survival advantage.
- **Recovery — retain.** Exact carried/equipped-origin custody has paired correctness coverage. W5 saves a paid action in quiet/pursuit/acid/busy-dog settings; ordinary pickup reaches the same portable objective, a free dog's custody removes the shortcut, and entry hazards still apply. No binary-success advantage or free retrieval from someone else's inventory is claimed.
- **Focused — retain for selective exposure.** W3's actual mixed-alliance healing and broad allied-group reversal provide the use case; payload review documents the lost broad ground-control coverage. Current W7 has no superior Focused lane-holding result. No benefit is assigned to an inactive purchased button. See `payload-precision-gate.md`.

The whole finite-stock W6 package does not dominate an alternative: current 100-seed all-five-plus-water secures 65 objectives versus bank 69 and water/acrobatics 74, with both difference intervals wider than 20 points. This is a fixed common-policy comparison, not optimized play of all skills; unused active buttons receive no causal credit.
